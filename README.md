# Transformer BOM Quality Analytics
Excel case study with a reproducible Python data-quality review, aligned to BOM, master-data and manufacturing analyst work.

## What is included
- [Transformer_BOM_Quality_Analytics.xlsx](Transformer_BOM_Quality_Analytics.xlsx): original synthetic workbook, renamed for clarity.
- [scripts/validate_bom.py](scripts/validate_bom.py): read-only source checks and KPI reconciliation.
- [scripts/test_validate_bom.py](scripts/test_validate_bom.py): four regression tests for duplicates, invalid measures, revision flags and repeated units.
- [reports/validation.json](reports/validation.json): generated record-level findings, source hash and KPI comparisons.
- [Data dictionary](docs/data_dictionary.md) and [case study](docs/case_study.md).
- `assets/`: saved workbook screenshots; these are not regenerated by the validator.

## Run from the repository root
```bash
python -m pip install -r requirements.txt
python scripts/validate_bom.py
python -m unittest discover -s scripts -p 'test_*.py'
```
The workbook is read without modification. Reports are overwritten deterministically for the same input. A data error or KPI mismatch produces a nonzero exit code; review flags alone do not.

## Checked results
120 error events and 100 revision entries; 25 unchanged-revision review flags. Four summary KPIs reconcile to two decimals. No Unit_ID overlaps exist between the error and revision tables, so a joined error/revision analysis is unsupported. Full definitions and limits are in the case study.
